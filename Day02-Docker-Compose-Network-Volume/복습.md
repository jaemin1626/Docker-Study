# Day 02 복습 - Docker Compose / Network / Volume

## 1. Docker Compose

Docker Compose는 여러 개의 컨테이너를 하나의 프로젝트처럼 정의하고 관리하는 도구이다.

```yaml
services:
  backend:
    build: ./backend

  db:
    image: postgres:17

  redis:
    image: redis:alpine
```

실행:

```bash
docker compose -f compose.yml up -d
```

- `-f` : 사용할 Compose YAML 파일 지정
- `up` : 정의된 서비스 생성 및 실행
- `-d` : Detached 모드로 실행하여 터미널을 반환

---

## 2. `services`와 컨테이너

```yaml
services:
  backend:
  db:
  redis:
```

`backend`, `db`, `redis`는 **Service 이름**이다.

일반적으로 각 Service를 기반으로 컨테이너가 생성된다.

```text
Compose
├── backend Service → Backend Container
├── db Service      → PostgreSQL Container
└── redis Service   → Redis Container
```

Compose 네트워크에서는 Service 이름을 DNS 이름처럼 사용할 수 있다.

```text
backend:8000
db:5432
redis:6379
```

따라서 컨테이너 IP를 직접 지정할 필요가 없다.

---

## 3. `image`와 `build`

### 3.1 기존 이미지 사용 - `image`

Redis, PostgreSQL, Nginx처럼 이미 만들어진 이미지를 사용할 경우:

```yaml
services:
  redis:
    image: redis:alpine

  db:
    image: postgres:17
```

`image:`는 **이미 만들어져 있는 이미지를 사용한다**는 의미이다.

```text
postgres:17 Image
      ↓
   Container
```

### 3.2 직접 만든 Dockerfile 사용 - `build`

내가 개발한 Backend처럼 직접 이미지를 만들어야 한다면:

```yaml
services:
  backend:
    build: ./backend
```

폴더 구조:

```text
project/
├── compose.yml
└── backend/
    ├── Dockerfile
    ├── main.py
    └── requirements.txt
```

Compose는 기본적으로:

```text
./backend/Dockerfile
```

을 사용하여 이미지를 빌드한다.

```text
Dockerfile
    ↓ build
  Image
    ↓
Container
```

### 핵심

```text
image: → 기존 이미지 사용
build: → Dockerfile로 이미지 생성 후 사용
```

---

## 4. `build.context`와 `dockerfile`

다음 두 설정은 기본 Dockerfile을 사용한다면 사실상 같은 의미이다.

### 간단한 방법

```yaml
backend:
  build: ./backend
```

### 상세하게 지정하는 방법

```yaml
backend:
  build:
    context: ./backend
    dockerfile: Dockerfile
```

여기서:

```text
context: ./backend
         └── Docker Build의 기준 경로

dockerfile: Dockerfile
            └── 사용할 Dockerfile
```

Dockerfile 이름을 다르게 지정할 수도 있다.

```yaml
backend:
  build:
    context: ./backend
    dockerfile: Dockerfile.dev
```

예:

```text
backend/
├── Dockerfile
├── Dockerfile.dev
├── Dockerfile.prod
├── main.py
└── requirements.txt
```

`Dockerfile.dev`와 `Dockerfile.prod`도 Dockerfile이며, 용도에 따라 파일 이름만 다르게 지정한 것이다.

---

## 5. `environment`

Compose의:

```yaml
environment:
  POSTGRES_PASSWORD: example-password
```

는 `docker run`의 `-e`와 같은 역할이다.

```bash
docker run \
  -e POSTGRES_PASSWORD=example-password \
  postgres:17
```

즉 컨테이너 내부 프로그램에 **환경변수를 전달**한다.

```text
Compose

environment:
  KEY: VALUE

      ≈

docker run -e KEY=VALUE
```

---

## 6. Docker Network와 Container IP

같은 Docker Network에 있는 컨테이너들은 각각 다른 IP를 할당받는다.

```text
Docker Network
│
├── Backend    172.18.0.2
├── PostgreSQL 172.18.0.3
└── Redis      172.18.0.4
```

하지만 컨테이너 IP는 컨테이너 재생성 등에 따라 변경될 수 있다.

따라서 직접 IP를 사용하는 것보다 **Service 이름을 사용하는 것이 좋다.**

```text
Backend
   │
   ├──→ db:5432
   │
   └──→ redis:6379
```

Compose에서는 같은 네트워크의 Service 이름을 DNS 이름처럼 사용할 수 있다.

---

## 7. IP와 Port

IP는 **어떤 Host/Container인지**를 나타내고, Port는 그 안의 **어떤 프로그램/서비스인지**를 나타낸다.

```text
172.17.0.2:80
│           │
IP          Port
```

대표적인 Port:

```text
22   → SSH
80   → HTTP
443  → HTTPS
5432 → PostgreSQL
6379 → Redis
8000 → FastAPI 등에서 자주 사용
```

### 중요

Port는 Docker가 자동으로 만들어주는 것이 아니다.

컨테이너 내부에서 실행되는 프로그램이 특정 Port에서 **Listen**해야 한다.

예를 들어:

```text
Nginx
  ↓
Port 80 Listen
```

또는:

```text
FastAPI / Uvicorn
  ↓
Port 8000 Listen
```

---

## 8. Port Mapping

Compose에서:

```yaml
ports:
  - "8080:80"
```

의 의미:

```text
HOST PORT : CONTAINER PORT

8080      : 80
```

외부에서 접근하면:

```text
Client
   │
   ▼
HostIP:8080
   │
   ▼
Docker Port Mapping
   │
   ▼
Container:80
```

### 여러 컨테이너가 같은 내부 Port를 사용할 수 있다

예를 들어 세 컨테이너가 모두 내부적으로 Port `80`을 사용해도 문제가 없다.

```text
Host :8080 → Container A :80
Host :8081 → Container B :80
Host :8082 → Container C :80
```

각 컨테이너는 서로 다른 네트워크 공간을 가지고 있기 때문이다.

---

## 9. 특정 Host IP에 Port Binding

다음과 같이 Host IP까지 지정할 수 있다.

```yaml
ports:
  - "127.0.0.1:8082:80"
```

형식:

```text
HOST_BIND_IP : HOST_PORT : CONTAINER_PORT
```

따라서:

```text
127.0.0.1:8082
       ↓
Docker
       ↓
Container:80
```

`127.0.0.1`에 바인딩하면 해당 Docker Host 내부에서만 접근할 수 있다.

### Docker Port Mapping과 Firewall의 차이

Docker의:

```text
-p
```

는

> **Host의 어디에 Container 서비스를 노출할 것인가**

를 결정한다.

반면 Firewall은:

> **어떤 외부 Source IP의 접근을 허용할 것인가**

를 결정한다.

## 10. Bind Mount

예:

```yaml
volumes:
  - ./Dataset:/workspace/Dataset
```

Host의 실제 폴더를 Container에 연결한다.

```text
Host
./Dataset
    ⇅
Container
/workspace/Dataset
```

Host와 Container가 같은 데이터를 바라본다.

따라서 Container에서:

```text
/workspace/Dataset/test.jpg
```

를 생성하면 Host에서도:

```text
./Dataset/test.jpg
```

를 확인할 수 있다.

### 주로 사용하는 대상

```text
Dataset
Source Code
Model
Config
Log
```

처럼 사용자가 Host에서도 직접 확인하거나 수정해야 하는 파일에 적합하다.

---

## 11. Docker Volume

예:

```yaml
services:
  db:
    image: postgres:17
    volumes:
      - postgres-data:/var/lib/postgresql/data

volumes:
  postgres-data:
```

여기서:

```text
postgres-data
```

는 **Docker가 관리하는 Named Volume**이다.

그리고:

```text
/var/lib/postgresql/data
```

는 PostgreSQL Container 내부의 데이터 저장 경로이다.

구조:

```text
Docker Volume
postgres-data
      ⇅
PostgreSQL Container
/var/lib/postgresql/data
```

Container를 삭제해도 Volume을 삭제하지 않는 한 데이터는 유지된다.

Docker Volume도 결국 Host의 실제 디스크에 저장된다.

다만 사용자가 Host 경로를 직접 지정하는 것이 아니라 **Docker가 저장 위치를 관리**한다.

---

## 12. Bind Mount vs Docker Volume

| 구분 | Bind Mount | Docker Volume |
|---|---|---|
| Host 경로 | 사용자가 직접 지정 | Docker가 관리 |
| 데이터 영속성 | O | O |
| Host에서 직접 관리 | 편리 | 보통 Docker를 통해 관리 |
| 대표 용도 | Dataset, Code, Model, Config | DB, Redis, 서비스 내부 데이터 |

### 쉽게 기억하기

```text
내가 직접 보고 수정해야 하는 파일
          ↓
      Bind Mount


애플리케이션이 관리하고
데이터만 영속적으로 보존
          ↓
     Docker Volume
```

## 13. `container_name`

Compose에서도 컨테이너 이름을 직접 지정할 수 있다.

```yaml
services:
  backend:
    container_name: my-backend
    build: ./backend
```

그러면 실제 컨테이너 이름은:

```text
my-backend
```

이 된다.

하지만 `container_name`은 필수가 아니다.

지정하지 않으면 Compose가 자동으로 이름을 생성한다.

예를 들어 프로젝트 이름이 `mlops`라면:

```text
mlops-backend-1
mlops-db-1
mlops-redis-1
```

같은 형태가 될 수 있다.

### Service 이름과 Container 이름은 다르다

```yaml
services:
  backend:
    container_name: my-backend
```

여기서:

```text
backend
   ↓
Service 이름

my-backend
   ↓
Container 이름
```

컨테이너 간 통신에서는 보통 **Service 이름**을 사용한다.

```text
backend:8000
db:5432
redis:6379
```

또한 `container_name`을 고정하면 동일 Service를 여러 컨테이너로 Scale할 때 제약이 생길 수 있으므로 반드시 지정할 필요는 없다.

# 14. 최종 Compose 예제

폴더 구조:

```text
project/
├── compose.yml
│
├── backend/
│   ├── Dockerfile
│   ├── main.py
│   └── requirements.txt
│
└── frontend/
    ├── Dockerfile
    └── ...
```

`compose.yml`:

```yaml
services:

  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    ports:
      - "8000:8000"

  frontend:
    build: ./frontend
    ports:
      - "8080:80"

  db:
    image: postgres:17
    environment:
      POSTGRES_PASSWORD: example-password
    volumes:
      - postgres-data:/var/lib/postgresql/data

  redis:
    image: redis:alpine

volumes:
  postgres-data:
```

구조적으로 보면:

```text
compose.yml
│
├── backend
│   └── ./backend/Dockerfile
│           ↓
│         Build
│           ↓
│         Image
│           ↓
│       Container
│
├── frontend
│   └── ./frontend/Dockerfile
│           ↓
│         Build
│           ↓
│         Image
│           ↓
│       Container
│
├── db
│   └── postgres:17
│           ↓
│       Container
│           │
│           └── postgres-data Volume
│
└── redis
    └── redis:alpine
            ↓
        Container
```

실행:

```bash
docker compose -f compose.yml up -d
```

# 핵심 복습

```text
Docker Compose
      │
      ▼
services:
      │
      ├── backend
      │      └── build: ./backend
      │              ↓
      │          Dockerfile
      │              ↓
      │            Image
      │              ↓
      │          Container
      │
      ├── db
      │      └── image: postgres:17
      │              ↓
      │          Container
      │              ↓
      │       Docker Volume
      │
      └── redis
             └── image: redis:alpine
                     ↓
                 Container
```

### 최종적으로 기억할 것

1. `services:` 아래에 실행할 Service들을 정의한다.
2. `image:`는 이미 만들어진 이미지를 사용한다.
3. `build:`는 지정한 경로의 Dockerfile을 이용해 이미지를 만든다.
4. `environment:`는 `docker run -e`와 같은 역할이다.
5. Compose는 같은 프로젝트의 Container들을 Network로 연결한다.
6. Container 간에는 IP보다 `db`, `redis`, `backend` 같은 Service 이름을 사용하는 것이 좋다.
7. `ports:`는 `HOST_PORT:CONTAINER_PORT` 형식으로 외부 접근을 연결한다.
8. Bind Mount는 Host 경로를 직접 연결한다.
9. Docker Volume은 Docker가 저장 위치를 관리한다.
10. `container_name:`으로 이름을 직접 지정할 수 있지만 필수는 아니다.
11. `docker compose -f compose.yml up -d`로 전체 서비스를 한 번에 올릴 수 있다.
