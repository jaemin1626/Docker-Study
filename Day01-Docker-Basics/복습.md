8~9번 복습 — 컨테이너 IP와 포트 매핑

기존 [1일차 학습 내용](README.md)의 **8. 컨테이너 가상 IP, eth0, lo**와 **9. 포트 매핑**을 복습하는 문서입니다.

> **핵심 한 줄: IP는 어느 컨테이너/호스트인지, 포트는 그 안의 어느 프로그램인지 구분하며, `-p 호스트포트:컨테이너포트`는 둘 사이의 전달 경로를 설정합니다.**

아래 설명은 일반적인 Linux bridge 네트워크를 기준으로 합니다. `host`, `none` 같은 네트워크 모드에서는 구성이 다릅니다. IP 주소는 이해를 돕기 위한 예시입니다.

## 1. 컨테이너마다 IP가 자동으로 배정된다

같은 Docker 네트워크에서 컨테이너 여러 개를 실행하면, Docker는 일반적으로 사용 가능한 **서로 다른 내부 IP를 자동으로 할당**합니다. 같은 이미지로 만들었어도 컨테이너는 각각 독립적입니다.

```text
Docker Host
|
+-- Docker bridge network
    |
    +-- Container A : 172.17.0.2
    +-- Container B : 172.17.0.3
    +-- Container C : 172.17.0.4
```

반드시 위 주소나 순서로 배정되는 것은 아닙니다. 컨테이너 IP는 해당 Docker 네트워크 내부 주소이며, 외부 PC에서는 보통 호스트 IP와 공개한 포트로 접속합니다.

**한 줄 요약: 같은 Docker 네트워크의 컨테이너들은 보통 서로 다른 IP를 자동으로 받는다.**

## 2. IP와 Port는 서로 다른 개념이다

| 구분 | 답하는 질문 | 예시 |
| --- | --- | --- |
| IP 주소 | 어느 컨테이너 또는 호스트인가? | `172.17.0.2` |
| Port 번호 | 그 안의 어느 프로그램에 연결할 것인가? | `22`, `80`, `8000` |

```text
172.17.0.2:80
|          |
|          +-- Port: 그 안에서 요청을 받을 프로그램의 창구
+------------- IP: 대상 컨테이너의 주소
```

IP를 아파트 주소에 비유하면, 포트는 그 안의 창구 번호에 가깝습니다. **22, 80, 8000은 가상 IP가 아니라 TCP/UDP 포트 번호**입니다.

| 포트 예시 | 흔히 사용하는 프로그램/서비스 |
| --- | --- |
| `22` | SSH 서버 |
| `80` | Nginx 같은 HTTP 웹 서버 |
| `8000` | FastAPI 등을 실행하는 개발 서버 |

위 번호는 관례나 설정 예시입니다. 포트 번호가 프로그램을 자동으로 설치하거나 결정하지는 않으며, 프로그램 설정에 따라 다른 포트를 사용할 수 있습니다.

**한 줄 요약: IP는 대상의 주소, 포트는 그 대상 안에서 프로그램이 사용하는 통신 창구다.**

## 3. 컨테이너를 만들었다고 80번에서 웹 서버가 기다리지는 않는다

컨테이너 생성만으로 80번 포트가 자동으로 웹 서비스를 제공하는 것은 아닙니다. **Nginx 같은 프로그램이 실행되어 해당 포트에서 listen해야** 요청에 응답할 수 있습니다. `listen`은 프로그램이 그 포트에서 연결 요청을 기다리는 상태를 뜻합니다.

```text
Container :80 --> Nginx listening --> HTTP response
Container :80 --> No listener     --> No web service
```

Ubuntu 컨테이너에서 셸만 실행했다면 웹 서버가 자동으로 생기지 않습니다. `-p 8080:80`을 붙여도 웹 서버를 설치하거나 실행해 주지는 않습니다. 이미지의 `EXPOSE 80` 역시 포트 사용 정보를 알릴 뿐, 프로그램 실행이나 호스트 포트 공개를 대신하지 않습니다.

**한 줄 요약: 포트에서 실제로 기다리는 프로그램이 있어야 통신할 수 있다.**

## 4. -p 8080:80은 호스트에서 컨테이너로 전달하는 설정이다

```bash
docker run -d --name review-web-a -p 8080:80 nginx:alpine
```

```text
-p 8080:80
   |    |
   |    +-- Container port: Nginx가 내부에서 사용하는 80
   +------- Host port: 클라이언트가 접속할 8080

Browser
   |
   | http://HOST_IP:8080
   v
Host :8080
   |
   | Docker port mapping
   v
Container A (172.17.0.2) :80
   |
   v
Nginx listening on port 80
```

- 왼쪽 `8080`: 호스트에서 사용할 포트입니다.
- 오른쪽 `80`: 컨테이너 내부 프로그램이 요청을 기다리는 포트입니다.
- **Docker가 80번을 임의 배정한 것이 아닙니다.** Nginx의 설정이 80번이므로 매핑 대상도 80번으로 지정한 것입니다.
- 프로그램이 내부 8000번에서 기다린다면 매핑도 예를 들어 `-p 8080:8000`으로 맞춰야 합니다.

현재 PC에서 Docker를 실행한다면 `http://localhost:8080`, 원격 서버에서 실행한다면 `http://서버IP:8080`으로 접속합니다. 컨테이너 내부 프로그램은 컨테이너 네트워크 인터페이스에서 요청을 받아야 합니다. 내부 `127.0.0.1`에만 바인딩되어 있으면 일반적인 포트 매핑으로 접근할 수 없습니다.

**한 줄 요약: 왼쪽은 호스트 입구, 오른쪽은 실제 프로그램이 기다리는 컨테이너 내부 포트다.**

## 5. 여러 컨테이너가 내부 80번을 동시에 사용할 수 있다

컨테이너마다 네트워크 공간이 분리되고, 같은 네트워크에서는 서로 다른 IP를 가지므로 모두 내부 80번 포트를 사용할 수 있습니다.

```text
172.17.0.2:80 --> Container A / Nginx
172.17.0.3:80 --> Container B / Nginx
172.17.0.4:80 --> Container C / Nginx
```

포트 번호는 같아도 `IP:Port` 조합이 다르므로 충돌하지 않습니다. 호스트의 같은 IP와 같은 프로토콜에서 여러 컨테이너로 공개할 때는 **서로 다른 호스트 포트**를 사용합니다.

```text
Host                       Docker network
:8080 -------------------> A  172.17.0.2:80
:8081 -------------------> B  172.17.0.3:80
:8082 -------------------> C  172.17.0.4:80
```

앞 절에서 A를 실행했다면 B와 C는 다음처럼 추가할 수 있습니다. 예제의 컨테이너 이름과 호스트 포트는 사용 중이지 않아야 합니다.

```bash
docker run -d --name review-web-b -p 8081:80 nginx:alpine
docker run -d --name review-web-c -p 8082:80 nginx:alpine
```

같은 호스트 IP의 TCP 8080번을 A와 B에 중복으로 매핑하려 하면 충돌합니다. 호스트의 8080번과 컨테이너의 80번은 서로 다른 네트워크 공간의 포트입니다.

**한 줄 요약: 내부 포트는 모두 80이어도 되고, 같은 호스트 IP에 공개하는 포트는 8080·8081·8082처럼 나눈다.**

## 6. 컨테이너 IP를 외우기보다 서비스 이름을 사용한다

컨테이너를 삭제하고 다시 만들면 IP가 바뀔 수 있습니다. 따라서 애플리케이션 설정에 `172.17.0.2` 같은 주소를 고정해서 적으면 재생성 후 연결이 끊길 수 있습니다.

Docker Compose에서는 **같은 Compose 네트워크에 연결된 서비스끼리 서비스 이름으로 통신하는 방식**을 권장합니다. 예를 들어 `web` 서비스가 내부 80번에서 기다린다면 다른 서비스는 `http://web:80`으로 연결합니다.

```text
Another service -- http://web:80 --> web service
                                      |
                                      +-- IP may change on recreation
```

서비스 이름은 Docker 내부 네트워크에서 사용하는 이름입니다. 호스트 브라우저에서는 보통 `http://localhost:8080`처럼 공개한 호스트 포트로 접속합니다. 기본 bridge와 달리 사용자 정의 bridge 네트워크에서는 컨테이너 이름으로도 통신할 수 있습니다.

**한 줄 요약: IP는 바뀔 수 있으므로 Compose 내부 통신에는 서비스 이름과 내부 포트를 사용한다.**

## 빠른 복습

1. `172.17.0.2:80`에서 IP는? **172.17.0.2**
2. `22`, `80`, `8000`은 가상 IP인가? **아니요. 포트 번호입니다.**
3. 컨테이너만 만들면 80번에서 웹 페이지가 나오는가? **아니요. 웹 서버가 실행되어 listen해야 합니다.**
4. `-p 8080:80`의 80은 Docker가 자동으로 고른 번호인가? **아니요. 내부 프로그램의 포트에 맞춰 지정한 번호입니다.**
5. A와 B가 모두 내부 80번을 사용해도 되는가? **네. 서로 독립된 네트워크 공간과 다른 IP를 사용합니다.**
6. 호스트에서는 어떻게 구분하는가? **8080 -> A:80, 8081 -> B:80처럼 매핑합니다.**
7. Compose에서 IP가 바뀌는 문제는 어떻게 줄이는가? **같은 네트워크에서 서비스 이름을 사용합니다.**
